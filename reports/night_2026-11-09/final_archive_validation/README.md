# Повторяемая проверка финальной поставки

`validate.py` проверяет текущие выбранные образы или будущий точный ZIP. Старых
констант v3, SHA архива и числа 64 файлов здесь нет. Источник ожидаемых 12 файлов
агента — `../selection.json`; контрольные суммы из ZIP сверяются с манифестом.

Проверка на выбранных root-образах пройдена на linux/arm64 и linux/amd64.
Результат — `preflight_root/validation.json`, отдельные команды, stdout/stderr
и подробности — в подпапках платформ. Внешних API и генераций модели: 0.

На каждой платформе проверены:

- настоящий CLI, SDK и пять искусственных сюжетов прежней проверки: математика,
  CSV-соединение, поиск, исправление исходника и отказ при недостатке сведений;
- одна пакетная правка двух функций одного файла, пять действительно выполненных
  публичных тестов и закреплённый README на обоих запросах задачи;
- правильное место answer.txt, сохранность исходных тестов/данных, одна строка
  отчёта на задачу и равенство расхода квитанциям локального HTTP-сервера;
- прежние 13 тестов исполнителя и шесть случаев __main__/unittest/pickle/argv;
- строка assert в traceback, запрет изменения прав и владельца;
- положительный контроль фиктивной метки окружения, реальный Linux guard,
  запрет четырёх native-импортов в дочернем коде и шесть fail-closed случаев;
- SymPy, точный LP-расчёт и соответствие всех 12 файлов образа selection.json.

Существующие фиксированные сценарии используются через небольшие обёртки.
В старом сценарии семантики меняется только путь `/source` на `/app`: проверка
исполняет код установленного образа. Действия агента и production-функции не
подменяются. HTTP-сервер возвращает заранее заданные ответы локально внутри
контейнера; это проверяет интеграцию, а не качество Qwen.

Контейнеры запускаются с отключённой внешней сетью, неизменяемой корневой
файловой системой, временными /tmp и /work, cap-drop ALL, no-new-privileges,
ограничениями CPU/памяти/процессов и только фиктивным окружением.

## После появления ZIP

Передать путь и независимо зафиксированный SHA-256:

```bash
.venv/bin/python reports/night_2026-11-09/final_archive_validation/validate.py \
  --archive /absolute/path/to/final.zip \
  --expected-sha SHA256_FROM_SIDECAR \
  --output reports/night_2026-11-09/final_archive_validation/exact_zip
```

Папка результата должна быть новой. Скрипт отклоняет дубликаты и небезопасные
пути, проверяет размер, распаковывает архив, сверяет каждый файл и размер по
манифесту, обязательные документы и runtime selection. Поиск секретов проходит
по всем байтам, включая README и манифест, с порогом sk-16. Значения находок
не печатаются. Произвольные неизвестные секреты такой поиск гарантированно
обнаружить не может.

Далее обе архитектуры собираются именно из распаковки с лимитом 1000 секунд
на сборку и 4 ГБ на размер образа. Все описанные испытания повторяются уже
на этих образах. После них сверяются ZIP, исходники и сборочные файлы.

Текущий preflight ещё не подтверждает точный ZIP, качество модели или
официальную приёмку организаторов. Упаковка в этом этапе не запускалась.

## Выбор файла окончательного решения

По умолчанию используется `../selection.json`. Если root фиксирует другой
файл решения, передать `--selectionPath reports/night_2026-11-09/FILE.json`.
Его относительный путь и SHA сверяются с тем же файлом внутри ZIP и записываются
в отчёт. Поле `coding_json_mode` должно быть bool; при отсутствии оно равно false.
Проверяющий передаёт это ожидание в контейнер и проверяет response_format
каждого coding-запроса; у всех остальных типов поле должно отсутствовать.

Скрипты прежнего успешного preflight сохранены без изменений в
`preflight_root/validation_scripts_at_check/`; их хеши равны историческому
validation.json. Небольшое новое условие проверено на семи скалярных fixtures
(см. selection_format_extension_check.json), без сборки и API. Следующий запуск
точного ZIP повторит испытания уже обновлённой обёрткой.
