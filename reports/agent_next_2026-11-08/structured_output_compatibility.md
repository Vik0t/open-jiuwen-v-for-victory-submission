# Корректный JSON без нового слоя агента

**Выданный бесплатный DeepCode с `Qwen3.8-27B` принял оба режима:
`response_format=json_object` и `response_format=json_schema`.** Проверена схема
с шестью текущими действиями, `oneOf`, обязательными полями и запретом лишних
полей. Производственный код и прежние заморозки не менялись.

## Три короткие пробы

В каждой: 128 выходных токенов максимум, `temperature=0`,
`enable_thinking=False`, одна попытка, чтение до 180 секунд, подключение до
10 секунд, маршрут en0. Официальный NeuralDeep не использовался.

| Режим и проверка | HTTP | Вход / выход | Результат |
|---|---:|---:|---|
| `json_object`; промпт просит ответить обычным текстом | 200 | 31 / 23 | Валидный JSON, без гарантии структуры действия |
| Строгая схема шести действий; короткая программа с кавычками и переводом строки | 200 | 46 / 30 | Действие `python`, соответствует схеме, код компилируется |
| Та же схема; промпт требует запрещённый `action=shell` и неверный тип `code=true` | 200 | 34 / 15 | Допустимое по схеме действие `write` |

Время ответа: 0,22–0,44 секунды. Всего **111 входных и 68 выходных токенов**,
то есть **79,1** единицы `выход + вход/10`; токенов рассуждений — ноль.
В конфликтной пробе модель не выполнила текстовую просьбу, но соблюла схему.
Это свидетельство работы ограничения, а не просто принятого и проигнорированного
параметра. Три короткие пробы не устанавливают надёжность на длинных программах.

Числовые результаты и хеши ответов:
[structured_output_probe.json](structured_output_probe.json).
Запрошенная схема и воспроизводимый код:
[structured_output_probe.py](structured_output_probe.py).
Ответы не исполнялись; короткая программа только проверена компилятором.

## Совместимость с нашим openJiuwen

Установленный `openjiuwen==0.1.20` разрешает дополнительные поля в
`ModelRequestConfig`. Конфигурацию можно передать так:

```python
extra_body={
    "chat_template_kwargs": {"enable_thinking": False},
    "response_format": {"type": "json_schema", "json_schema": schema_spec},
}
```

Это подтверждено через настоящий путь `Gateway → ReActAgent → Runner → HTTP`,
с локальным подставным транспортом: **одно HTTP-сообщение, ноль внешних
запросов**. Поля схемы и отключения рассуждений дошли в тело запроса без
изменения. Результат — [structured_output_sdk_probe.json](structured_output_sdk_probe.json),
проверка — [structured_output_sdk_probe.py](structured_output_sdk_probe.py).

**В обвязке обнаружена и отдельно исправлена потеря параметра:** прежняя
`compare.py::without_thinking` целиком заменяла `extra_body` и удаляла бы
новую схему. В живом файле для будущих заморозок теперь объединяются поля;
исторические снимки оставлены неизменными. Наличие `response_format`
подтверждено в HTTP-теле минимального кандидата; подробности ниже.

Формат `json_object` гарантирует только JSON, а схема дополнительно описывает
его структуру. Такое различие и способ передачи описаны в первичной
[документации Qwen](https://docs.qwencloud.com/developer-guides/text-generation/structured-output).
Поддержка зависит от сервера размещения модели; для нашего DeepCode она
проверена непосредственно. Документация
[vLLM](https://docs.vllm.ai/en/latest/features/structured_outputs/)
также описывает передачу схемы через этот параметр; какой сервер стоит за
DeepCode, эти пробы не устанавливают.

## Что проверить следующим сравнением

Сначала провести небольшое отдельное сравнение на знакомых задачах: обычный
JSON по инструкции, `json_object`, строгая схема. Зафиксировать одинаковые
исходные файлы, первый кандидат, промпт, выходной предел и число повторов.
Взять примеры с ошибками кавычек/переводов строк, обрывом по пределу длины и
контрольные примеры, где обычный JSON уже работал. Не использовать приватные
ожидаемые ответы в запросах модели.

Из старых неразбираемых ответов нельзя получить результат нового режима
простым повторным разбором: он действует при генерации. Для честной пары
нужен сохранённый одинаковый запрос. Текущие записи хранят ответ и размер
запроса, но не полное тело; исходное состояние следует восстановить и затем
зафиксировать один раз для всех режимов, не выдавая его за побайтово исходный
HTTP-запрос прежнего запуска.

Считать отдельно долю валидного JSON, соблюдение схемы, компиляцию/успех
программы и правильность ответа. После этого — итоговые баллы полного агента
при равном общем бюджете на новом наборе. Иначе улучшение формата можно
ошибочно принять за улучшение решения.

Схема **не исправляет обрыв по пределу выходных токенов**, неверную математику,
пропущенное требование или неподходящее действие. Она увеличивает размер тела
запроса и наш консервативный резерв; влияние на фактический расход и допустимый
выходной предел нужно измерять. Поэтому это небольшой проверяемый кандидат
на улучшение, а не уже доказанная замена текущего агента.

## Минимальный кандидат для отдельного опыта

Создан `experiments/agent_next_2026-11-08/json_source` на точной копии
`v3_io180_source`. Строгая длинная схема в него **не добавлена**. Только
`Gateway.answer(..., json_output=False)` включает `response_format=json_object`
при явном `True`; единственный вызов в `compact.py` передаёт этот флаг.
Остальные исходники совпадают. Производственная версия root не менялась.

Точный [diff](json_candidate.patch) включает две правки кандидата и объединение
параметров в живой обвязке. Хеши — [json_candidate_source.json](json_candidate_source.json).
SHA256 дерева кандидата по отсортированному отображению «путь → SHA256»:
`983d3620d97eaa90c54909a4b3319cb63b91d70e187df2aff3b4fc66e4bed8be`.

Четыре проверки через настоящий openJiuwen с локальным транспортом подтвердили:
родительский запрос, кандидат без флага и кандидат с `False` имеют одинаковое
тело. Вариант `True` добавляет только `response_format=json_object`.
Отключение рассуждений сохранено. Внешних модельных запросов в этой проверке
**ноль**. Подробности — [json_candidate_wire_verification.json](json_candidate_wire_verification.json).

Это готовность к отдельному сравнению на прежних сорока задачах разработки,
а не результат такого сравнения и не улучшение на закрытом наборе.
