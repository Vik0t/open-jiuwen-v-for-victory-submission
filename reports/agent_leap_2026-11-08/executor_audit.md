# Проверка исполнителя и цикла агента

8 ноября 2026 года. Проверялся текущий код; модельные API и отложенные задачи не использовались. Все примеры ниже — отдельно созданные искусственные файлы в каталоге временных данных.

Исправлен прямой обход ограничения путей через `import __main__; __main__.root = Path('/')`. Политика теперь находится в замыкании функции запуска, а программа получает отдельное пространство имён. В `__main__` нет исходных `root`, `check_path` и таблицы защищённых путей; присваивание одноимённых атрибутов не изменяет действующую политику. Добавлена проверка попытки прочитать искусственный родительский файл после такого присваивания.

Это исправление конкретного обхода, а не превращение Python в полноценную изолированную среду. В Python остаются возможности анализа объектов и кадров выполнения, нативных расширений и изменения глобального состояния библиотек. Ограничения ресурсов и audit hook уменьшают риск обычных ошибочных действий; границы сети и файлов определяет окружение запуска. При проверке через Docker необходимо монтировать только рабочую папку задачи и нужный файл исполнителя, без секретов, чужих задач и закрытых метаданных. Наличие `/.dockerenv` само по себе не доказывает отсутствие сети или секретов. Условия конкурсного окружения контролируются организаторами.

Также исправлена потеря конечного ответа после длинного вывода: конкурсный исполнитель сохраняет последние 8192 байта stdout и stderr. Проверены длинная диагностика с последующим маркером ответа и сохранение последней строки ошибки; ограничение размера создаваемых файлов сохранено. Другие воспроизведённые различия переданы основному разработчику:

| Проверка | Наблюдение до изменения основным разработчиком | Требуемое действие |
|---|---|---|
| 9000 символов вывода, затем `submit_answer(21)` | До исправления конкурсный исполнитель терял маркер при коде возврата 0. | Исправлено: сохраняется хвост stdout и stderr; эксперимент должен вызывать тот же исполнитель. |
| `tempfile.TemporaryDirectory()` | Обычный Python внутри Docker проходит; конкурсная политика отказывает. | Эксперимент должен вызывать настоящий конкурсный исполнитель; временные файлы должны оставаться в рабочей папке. |
| Создать новый `calculation.txt`, затем сдать ответ | Сравнение всех текущих файлов принимает новый файл за изменение исходных данных и отвергает ответ. | Отличать исходные защищённые файлы от новых рабочих результатов. |
| Исправление кода на последнем разрешённом шаге | Открытые тесты проходят, но цикл возвращает `step_limit`, а `answer.txt` отсутствует. | Явно обработать завершение после последней проверенной правки. |

Проверки подтверждают конкретные механизмы и совместимость исполнения; они не измеряют качество решения новых задач и не являются конкурсным результатом.
